The playground

Code on the left, result on the right, updating as you type. Every lesson from Part 1 onward is built out of this. Break the examples — that is what they are for.

What this page is The playground component's own test page. It exercises every path: two panes, one pane, live update on and off, the fallback editor, and the copy button on both a secure origin and file://. Real lesson content starts in Part 1.

The controls

  • Live — updates the preview 300 ms after you stop typing. It starts switched off below 768px, because a preview that reflows on every keystroke is unpleasant on a phone.
  • Run — updates the preview now. This is the button to use on mobile.
  • Reset — puts the original example back, both panes.
  • Copy — copies the pane you are looking at, so HTML and CSS stay separate the way they will be in the exam.
  • Preview only — hides the editor and gives the result the full width, taller. Useful once an example gets bigger than a phone screen.

Two panes, one document

The tabs are HTML and CSS because that is how the exam is answered: one markup file and one stylesheet. They are assembled into a single document for the preview, so what you see is what a browser would do with those two files.

This example is the reason box-sizing: border-box goes at the top of every stylesheet. Both boxes ask for the same width. Only one of them gets it.

Break it deliberately

Most flexbox confusion comes from one fact: justify-content follows the main axis and align-items follows the cross axis, and flex-direction decides which is which. Reading that sentence does nothing. Changing one word and watching the boxes move does.

Closer to the exam

Four coloured cards is the single most common thing in these past papers — it appears in six of the twelve prototypes. Written badly it is four near-identical rule blocks. Written properly it is one block and one custom property.

One pane, when that is all there is

A playground does not have to have both. This one has no CSS at all, because character entities are about what the browser renders, not how it is styled.
